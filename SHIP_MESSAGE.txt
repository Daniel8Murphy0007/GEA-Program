v0.8.1 — THE KIT'S GATE READS THE KIT

v0.8.0 shipped whole - the commit, the tag, CI and the PyPI release all
green - and both kit builds went red at the same point: the kit's own gate,
twenty minutes in. Section BB, written that morning, read the launcher
templates out of tools/build_installer.py. A checkout has that file. An
installed kit has the package in site-packages and no tools/ at all, so the
section fell over before its first check.

The gate already had a way of telling the two apart - pyproject.toml beside
the package means a checkout - and the section did not use it. It does now,
and in a kit it does something better than reading a template: it reads the
launcher the kit actually installed beside its python/, found the way gea
doctor finds it. The kit's gate therefore checks the file the client will
double-click, which is the test that should have been there in the first
place.

Proven from an installed layout - the package in a venv's site-packages with
no checkout beside it and the launcher two levels up - with the full gate
run from there: 302 checks. The report samples are re-rendered from this
build. Nothing else changes.
