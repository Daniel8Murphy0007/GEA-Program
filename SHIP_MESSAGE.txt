v0.43.0 — REPORT HISTORY AND THE SIGNED DOSSIER

Two things this release adds: no report is lost when the next one is
written, and a well's record can be sent as one file that anyone can check.

Report history. A report is written to a fixed name, so the latest is
always where a reader expects it - and until now each new one replaced the
last. Every client report written in a workspace is now also kept in a
dated folder under reports/history, with each file's SHA-256 in an index.
The Reports tab lists every report's versions with links to each file.

The signed dossier. One zip holds a well's - or the pad's - reports, the
declarations behind them, the audit log and the hashes of the source
records, with a manifest of every file's SHA-256 signed with the site's own
Ed25519 key. The key is made on the site's machine the first time and never
leaves it; its fingerprint is on the Reports tab for the site to give its
clients. Inside every dossier is a checker that runs with plain Python and
nothing else: it says VALID when the signature and every file's hash hold.
Inside the workspace the check also says whether the source records and the
audit log still match what was signed, and each dossier names the one
before it, so a site's dossiers form one chain. A valid signature shows the
files are unchanged since signing; the page says plainly that it does not
show they are correct.

Section CL is new, three checks. The gate is 416 checks. The standalone
guard is clean.
