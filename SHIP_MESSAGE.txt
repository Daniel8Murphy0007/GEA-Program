v0.18.0 — THE BACKUP: THE SITE COPIED OFF THE MACHINE

The records are the product, and nothing in the package copied the site
anywhere. The doctor told a person to restore users.json "from a backup"
that no command wrote. gea backup writes it: one dated archive of the whole
site - every well's source and records, every station's source and live day
files, the configuration, the monitor, the reports, users.json, the audit
log, the patches, the schedule - with a manifest of every file's SHA-256
inside and the archive's own hash beside it, onto another disk or a share
(a folder inside the workspace is refused). --verify reads an archive
against its manifest and names what differs. --restore brings one back onto
an empty folder, verifies every file again, opens it as a workspace and
says what came back - because a backup nobody has restored is a hope.
--keep prunes the old ones. The doctor warns when there has never been a
backup or the last is more than a day old. On the dashboard, Audit / Update
carries the card: the folder, Back up now, Schedule daily.

Also in this ship: the attach step's tolerance for a tag run whose upload
loses to a run beside it (a second line; v0.17.1 removed the second run).

Section BL is new. The gate is 342 checks. The standalone guard is clean.
