v0.3.0 — THE DASHBOARD AS THE DOOR, AND THE PATCH PANEL

The dashboard is where the client works. gea/workspace.py (one folder per
site: wells from a file, the catalogue or a live map; the client's files copied
in verbatim and hashed; the version store; monitor logs; reports; jobs; an
append-only audit log with the SHA-256 of every input), gea/jobs.py (every
action a `gea` command with its log, status and return code; a scheduler),
gea/service.py (a standard-library HTTP service: the page, the reports, a JSON
API; salted PBKDF2 accounts; roles viewer < operator < approver < admin;
HttpOnly SameSite sessions; the page's own header on every action), and
gea/web/app.html (Home, Wells, Patch panel, Alarms, Approvals, Configuration,
Reports, Verification, Survey, Jobs, Administration; inline SVG trends;
keyboard-operable; light and dark; phone width).

The patch panel: gea/wits0.py (WITS Level 0 from the drill floor over TCP
connect, TCP listen or serial; the record-01 dictionary; an in-package sender,
`gea wits0-sim`), gea/witsml.py (WITSML 1.4.1 read-only client with an
in-package test store), gea/patches.py (supervised patches: reconnect with
backoff, heartbeat, latency, per-tag last values, daily record files, several
sources folded into one stream by priority), unit normalisation on every
mapping (`unit_in` beside `unit`). The alarm engine is now idempotent against
its event log, so re-processing adds nothing and acknowledgements persist.

CLI: gea workspace, gea serve, gea users, gea survey, gea wits0, gea witsml,
gea wits0-sim. Extras: serial; live now includes pyserial. Acceptance
sections AC (17) and AD (10): the service through real HTTP under three
roles, two live protocol loopbacks over real sockets, the supervisor losing
and regaining its sender. Gate 199/199 here and on the development machine;
standalone check 0 findings - the service and the ports add no dependency.
