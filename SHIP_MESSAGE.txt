v0.32.0 — THE SETUP CHECKLIST

Pad 3 has three wells in it, read and reported on, and nothing yet that
says where they are, whose they are, or that a copy of any of it exists
off the machine. The program knew all of that - each fact was a field it
could read - and said none of it in one place. This release adds the
Setup tab.

It is read from the workspace as it stands. An item is done because what
it asks for is there: a declared surface location and its datum, a
reference elevation with its source, a US Well Number, a site record that
names the client and holds every well, a backup folder off the machine, a
current backup, the daily schedule, reports newer than their data. Each
item carries its own form or button, and the command to paste where every
value is already known. Where the operator has to supply a value - a
position, an elevation, a number - the item says which values and where
they come from, and prints no command with stand-ins in it. The tab's
badge counts what is left; the Home page names the next item.

A drilling record's depth events are the one thing only a person can
check: against the daily drilling reports. That check is confirmed with a
note, kept with the name and the time, and stops counting if the record
changes.

Building it turned up two things. Declaring a well number put it in the
disposal block, which made any well a disposal well - every Pad 3 producer
would have become one. The number is now the well's identity. And a
drilling record whose gamma was flat in the kept interval was not written,
because one message used a word the client-report guard rejects. Both are
fixed and both are checked.

Section CA is new, three checks. The gate is 383 checks. The standalone
guard is clean.
