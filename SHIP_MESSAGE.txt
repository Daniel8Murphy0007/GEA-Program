v0.23.0 — THE FIELD PORTS: MODBUS RTU, DNP3, HART-IP

The three links a gauge panel on a pad actually offers, and the ones the
patch panel did not have. Modbus RTU - the RS-485 drop most surface-readout
panels are - framed and parsed by this program as the specification lays it
out, with no dependency: the serial line through pyserial, the same bytes
through a serial-to-Ethernet converter, or the stand-in slave that ships
with it. DNP3 - what pad RTUs and pipeline SCADA speak in North America - a
read-only master with the data link, transport and application layers each
as IEEE 1815 writes them: the integrity poll, the event poll, the confirms
the outstation asks for, the unsolicited response answered and read, every
analog, binary and counter variation with its flags, an event carrying the
outstation's own time as the source time. HART-IP - the transmitter itself,
asked for its identity, its loop current and its variables with their unit
codes and status.

Each is read-only in the code, not by policy: no write, no control, no time
set, no command that changes a device exists. Each refuses to run without
the site's map and its source. Each has a stand-in on the loopback so a site
rehearses before the panel is on the line, and each is one more protocol on
the Patch panel, supervised, restarted with backoff, folded into the well's
stream.

What it will not do: write to a device; clean a value the device flagged;
guess a map; give a static value a time the device did not send; parse past
an object it does not know.

Section BQ is new. The gate is 356 checks. The standalone guard is clean.
