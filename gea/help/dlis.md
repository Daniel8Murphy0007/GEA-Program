# The DLIS log

> A well log is delivered as DLIS (API RP66 V1); the LAS file is the export. This program reads the DLIS itself, as the standard lays the container out - the storage unit label, the visible records, the logical record segments with their predecessor and successor flags and trailers, the explicitly formatted records (file header, origin, channels, frames, parameters, tools, calibrations) as sets of objects under a template with the representation codes of Appendix B, the frame data records as the channel values in the frame's order - with no dependency, and hands the strata survey the same stream the LAS port does. Proven on a public, actually produced file: Schlumberger's MSCT station log of well 206/05a-3 (Faroe Petroleum, Fulla, 2011): 104 channels, 2 frames, 3,252 logical records read whole in a tenth of a second, 11 vendor-encrypted records skipped and named.

**The command**: `gea dlis --file log.dlis --info` describes the file - the storage set, the file header, the origin (well, field, company, producer, creation time, the programs that wrote it), every set and how many objects it holds, every channel with its units, representation code, dimension and long name, every frame with its index type, direction, spacing and range, and what was skipped (encrypted records by type; a set the reader could not parse, named). `gea dlis --file log.dlis --frame 800T --out frame.csv` writes a frame's channels as CSV (index first, a units row); `--to-las frame.las` writes it as LAS 2.0 so every other command ingests it. `gea survey --file log.dlis [--frame NAME]` runs the strata survey on a depth-indexed frame directly; the Files page detects a DLIS by its label and imports it as a well like a LAS.

**What it writes**: the frame as a stream - the first channel of the frame as the index (depth or time, as the frame's INDEX-TYPE says), each scalar numeric channel as a curve with the units the CHANNEL object states, the absent-value sentinel (-999.25) as missing - and the notes: a channel with a dimension other than one is read past and named, a non-numeric channel likewise, an encrypted record counted by type, a set the reader could not parse named with the reason. The origin's well, field, company and producer ride on the stream's metadata into the survey's provenance line.

**The number to check**: the frame's row count and index range against `--info`'s INDEX-MIN and INDEX-MAX (in the units the frame states; a 0.5 ms spacing unit against a ms channel is a factor of two, and both are printed), and the channel count against the frame's channel list less what the notes say was read past.

**What this page will not call a measurement**: a value from an encrypted record - the reader does not decrypt; the record is counted and named, nothing is guessed from it. A channel laid out by guess - a multi-dimensional channel, a representation code the reader does not decode, a frame whose channels have no CHANNEL object are each named and not laid out. A depth from a time-indexed frame - the survey refuses a frame whose index is not depth and names the frames the file holds. A second frame's values under the first's name - a file with several frames needs one named. A DLIS V2 or a LAS file - the label is checked and the reader says what it was given.
