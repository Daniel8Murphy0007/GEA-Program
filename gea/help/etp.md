# WITSML 2.x over ETP

> The live-port leg on the streaming protocol the newer rigs and stores speak: Energistics ETP v1.2 over WebSocket, Avro-encoded, with the real-time path of Protocol 21 (ChannelSubscribe) - the customer names the channels, subscribes, and the store pushes every new value as it is written.

**The command**: `gea etp --write-example-config etp.json`, then put the store's `url` (`ws://` or `wss://`), the bearer token's environment variable name under `auth`, and one entry per channel URI with its `tag_id`, `unit` and `tag_class`; `gea etp --config etp.json --seconds 60 --out floor --record session.jsonl` runs it. On the dashboard: Patch panel -> Add a patch -> `etp` (the example config is one click away); the patch supervisor keeps the subscription up, reconnects with backoff, and folds the records into the well's live stream like every other port. `gea etp-sim --port 9800` is a store with two channels of a synthetic disposal well for a site with no rig yet; `gea etp --selftest` runs the codec round-trip and a session against it on the loopback.

**What it writes**: one `SampleRecord` per DataItem the store pushes - the tag the mapping names for the channel's URI, the value, the unit the mapping declares (converted from the store's uom only when `unit_in` is given), GOOD or BAD with the rule, the store's own index as the source time (an ETP DateTime index is microseconds since the epoch; an ElapsedTime index is seconds from a declared start) and the arrival time as the ingest time, so the latency is measured per record. The session is recorded as received (the headers and the bodies, ChannelData as its counts) and `--replay` reproduces the session's shape. The handshake carries `Sec-WebSocket-Protocol: etp12.energistics.org`, `etp-encoding: binary` and the payload limits; the session asks for the customer roles of Discovery (3), Store (4) and ChannelSubscribe (21) and reads what the store supports; client message ids are even from 2 and the store's odd from 1; a ProtocolException is carried to the caller with its code and message.

**The number to check**: on the patch, `CONNECTED` with the tags, their units and the latency; on `gea etp`, the store's application name, the channels subscribed, and `missing` naming any URI the store did not return metadata for.

**What this page will not call a measurement**: a time for a depth-indexed sample - the arrival time stands as the record's time and the record says so. A tag it was not told - a channel the mapping does not name is counted as unmapped and left out, as every port here does. A unit it did not read - the store's uom is carried as declared and converted only when the mapping declares the input unit. A value from a message it could not decode - the message is counted as unreadable with its header and the stream carries on. A store that is not ETP - a client or a server without the subprotocol is refused at the handshake, not guessed at.
