# GEA-VPN - the private network between the programs

> The control panel, each pad's recorder, the operator's window and the client's reader run on separate computers in separate places; GEA-VPN joins them into one private network over the internet, so the office reaches every box at a fixed private address and nothing else on the internet can see any of them.

**The command**: the Administration tab's **GEA-VPN** card (admin). It is WireGuard - the VPN built into every Linux kernel and installed on Windows from wireguard.com - and GEA writes every key, address and configuration, so nothing is typed on a pad. One **hub** is needed: a small cloud server of the site's own, any Debian or Ubuntu machine with a public address (a rented virtual server of the smallest size is enough), reachable on UDP port 51820; every member connects out to it and it forwards between the office and each member - members never see one another. Make the network once: enter the hub's public name or address (`vpn.pad3site.com` or `203.0.113.10`) and click **Make the network** - the office member (this control panel, `10.77.0.2`) is made with it. Download `gea-vpn-hub.zip`, copy it to the hub and run there, once, `sudo sh install-hub.sh` (it installs WireGuard, opens the port, turns forwarding on and starts the tunnel at boot). Install WireGuard on this computer from wireguard.com (admin, once), click **Import tunnel(s) from file**, choose `gea-vpn.conf` from `gea-vpn-office.zip`, click **Activate**; the card's pill turns to `tunnel up`. Add a member per computer: its name (`Pad 3 box`) and its kind - `box` for a recorder (its page on 8780, reaches the office only), `operator` or `reader` for a window (reaches the office's control panel only), `office` for a second control panel - then **Add the member**; its address and `gea-vpn-pad-3-box.zip` appear in the table, and the hub installer must be run again (the hub's folder is written anew with every member). A box's zip holds `vpn.sh`: on the Pi, `sudo sh vpn.sh` once. A Windows member imports its `gea-vpn.conf` into WireGuard once. In the Field tab, pull from the box at its private address: `http://10.77.0.3:8780`. **Remove** takes a member out (its key is dropped from the hub when the installer runs again); **Make the files again** rewrites every folder and zip. From a terminal: `gea vpn --workspace C:\site --create vpn.pad3site.com`, `gea vpn --workspace C:\site --add "Pad 3 box" --kind box`, `gea vpn --workspace C:\site --remove pad-3-box`, `gea vpn --workspace C:\site --bundles`, `gea vpn --workspace C:\site` (the table).

**What it writes**: `keys\vpn\network.json` (owner-only; every member's private key, the hub's, and the pre-shared key per member) - the backup carries it, the dossier never does; under `exports\vpn\`: `hub\` (`gea-vpn.conf`, `install-hub.sh`, `README.txt`, zipped as `gea-vpn-hub.zip`) and one folder per member (`gea-vpn.conf` with the member's own private key, plus `vpn.sh` for a box or `README.txt` for a window, zipped as `gea-vpn-pad-3-box.zip` for `Pad 3 box`); the audit lines `vpn.create`, `vpn.hub`, `vpn.member.add`, `vpn.member.remove`, `vpn.bundles`, `vpn.bundle.download`. A member's zip holds its key: hand it over in person, or by a channel of its own, never by the same e-mail as anything else; a lost file is replaced by removing the member, adding it again and running the hub installer again.

**The number to check**: the card's pill - `tunnel up` means WireGuard on this computer has the `gea-vpn` tunnel active; `tunnel not up here` means it is not installed or not activated, and nothing private is reachable. In the table, **Last handshake** within the last two or three minutes for a member means its tunnel is up and talking to this computer (a keepalive every 25 s keeps it so behind a cellular modem); **Reachable** `yes` means the member's program answered on its port through the tunnel - a box's page on 8780, a window's control panel - and that is the address to pull from.

**What this page will not call a measurement**: a handshake is not a pull - a box reachable through the tunnel still has to be pulled in the Field tab for its files to become a station; the tunnel encrypts and addresses, it does not verify a file (the SHA-256 beside every record does that, through the tunnel or not); and the private addresses are the site's own convention - nothing of the network is known outside the hub and its members.

Related: `gea help recorder`, `gea help site`, `gea help backup`.
