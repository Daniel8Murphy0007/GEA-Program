# Install on Windows

> GEA-Program-Setup: the program installed for you like any Windows program - a window of its own, an icon in the notification area, Start-menu and desktop shortcuts, an Add/Remove Programs entry, upgrades in place - with no administrator rights and the site's data left where it is.

**The command**: download the setup from the release on GitHub (`GEA-Program-Setup-0.70.0.exe` for this version) and run it. It installs for you alone, under `%LOCALAPPDATA%\Programs\GEA-Program`, and asks for the site workspace - the folder that holds the wells, reports, records, accounts and keys. An existing one such as `C:\site` is used exactly as it is, its name included; for a new one (by default `%LOCALAPPDATA%\GEA-Program\site`) it also asks the site's name, which heads every report, and makes the workspace with it (left empty, the workspace is named after its folder; an administrator renames the site in Administration's site settings). Then the Start menu's **GEA-Program** (and the desktop shortcut) starts the control panel when it is not running and opens it in a window of its own. A newer setup installs over the older one: it stops the control panel, replaces the program, keeps the workspace and the choices made before. For a site's software deployment: `GEA-Program-Setup-0.70.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /WORKSPACE="C:\site" /SITENAME="Pad 3" /TASKS="desktopicon"` (`/SITENAME` names a workspace the setup makes; one that exists keeps its own name). From a terminal: `gea launch` does what the shortcut does, `gea launch --selftest` says what it would do, `gea tray --selftest` checks the icon.

**The window**: Microsoft Edge's app window (`msedge --app=`: the control panel with no tabs and no address bar, its own button on the taskbar, which shows the program's derrick and pins as GEA-Program, not as Edge), with a browser profile of its own (`%LOCALAPPDATA%\GEA-Program\window`, no extensions; the first time, Edge may say it signed that profile in to your Microsoft account - Got it), else Google Chrome's, else a tab in the default browser. Where the browser keeps no cookies (its settings or a policy block them), the sign-in page says so and the control panel holds the sign-in itself, in the window's address, until the window is closed. The control panel itself runs with no window of its own: `gea supervise` keeps it running in the background, starts it again when it asks for a restart, and writes everything it would have shown in a console - the start, the sign-ins, the jobs, a stop and why - to `records\console.log` in the workspace. No PowerShell or console window opens. The kit's `start-dashboard.cmd` still runs it in a console window, for a site that wants to watch it there.

**The icon**: in the notification area, teal while the control panel runs and grey while it does not; its tooltip says which and on what port, and a notification says so when the panel stops without being asked to from the icon. Its menu: Open the control panel (or a double click; when the panel is stopped, it is started first), Start it without a window, Stop it, Open the operator window, Open the site workspace folder, The control panel's log (`records\console.log`), Help (this page), Close this icon. The Start menu's **Stop GEA-Program** stops it too, with no window.

**The operator window**: the Start menu's **GEA-Program operator window** (or the icon's menu, or `gea operator`) opens the desktop window for one well at a time, apart from the control panel: pick a catalogue well with a measured temperature log (the KTB main hole, ODP Site 1027, IODP U1324 - an operator-tier well whose private files are not on this computer is left out of the list), hang a tool at a depth and see its rating checked against the well's measured temperature (a tool over its rating blocks the run), start the run and watch each station's pressure and temperature, the datasheet aging rates, the Volve F-12 reconciliation and its alerts, a LAS or historian file read in - with the sources of everything on view at the bottom, always. It has its own taskbar button with the derrick. It needs nothing the setup does not install (PyQt6 and matplotlib come with it); when it cannot open, a message box says why.

**Starting at sign-in**: the setup's "Start the control panel when I sign in to Windows" puts a GEA-Program shortcut in the Startup folder: the control panel starts in the background with its icon, and no window opens until you open one. The install kit's `register-service.cmd` (a scheduled task) does the same for a kit that was not installed by the setup.

**Other workspaces**: a site's report and dossier cover every well in its workspace, so a well that is not the site's - a demonstration, a well looked at for a client - goes in a workspace of its own. Administration, **Workspaces**, lists every workspace this computer has used; **Make it and open it** makes a new one in the folder named (beside the site's, never inside it or around it; with the same accounts, unless unticked) and opens its control panel in a window of its own on the next free port (8766, 8767, ...); **Open in its own window** opens one again. Each runs exactly as the Start menu's GEA-Program runs the site's, with its own wells, reports, keys and records. The list is kept in `%LOCALAPPDATA%\GEA-Program\workspaces.json`.

**What it writes**: the program under `%LOCALAPPDATA%\Programs\GEA-Program` (the install kit, and the package installed into the kit's own Python by its `install.cmd`, from its own wheels, with no network); `site-workspace.txt` there, the workspace you chose; the shortcuts; the Add/Remove Programs entry under the current user. Setup and uninstall never write into an existing workspace (a new one the setup makes, with its name, and leaves at that), never move it and never delete it, and will not take a workspace inside the program's own folder (which an upgrade replaces and the uninstaller removes). Uninstalling stops the control panel and its icon, then removes the program and what `install.cmd` added to it.

**The number to check**: Add/Remove Programs lists GEA-Program with the version you installed; `gea doctor --workspace C:\site` ends with `nothing blocks serving`; the Start menu's **Verify GEA-Program** runs the acceptance gate from the installation and ends with `[ACCEPTANCE] OK - N checks passed`. The release's build installs, upgrades and uninstalls the setup silently before it is published, with the control panel running, and checks the workspace untouched afterwards.

**Signed**: when the publisher's code-signing certificate is configured for the build, the setup is signed with it (Authenticode, timestamped) and Windows names the publisher; until then it ships unsigned and Windows SmartScreen says "unknown publisher" (More info, then Run anyway). The build's provenance holds either way: `gh attestation verify GEA-Program-Setup-0.70.0.exe -R Daniel8Murphy0007/GEA-Program`. The uninstaller the setup leaves behind is Inno Setup's own and is not signed separately.

**What this page will not call a measurement**: the icon's running or stopped is whether the control panel's port answers on this computer, read every three seconds - not whether every patch, job or report behind it is healthy (Home and the Verification page say that).

Related: `gea help start`, `gea help site`, `gea help https`, `gea help doctor`, `gea security`.
