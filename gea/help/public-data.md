# Public data

> A real pad from published records. The Utah FORGE project - the U.S. Department of Energy's geothermal field laboratory near Milford, Utah - publishes the rig recorders of five wells drilled through the same basin fill and granite between 2017 and 2023, under Creative Commons Attribution 4.0. This page turns those files into a site of its own, so the rig time, the roadmap, the drilling alerts and the benchmark run on real records whose figures anyone may check and repeat. The program does not contain the files and does not fetch them: the site downloads them in a browser, and the program checks each against the size and the SHA-256 it had when this release was checked with it.

**The command**: the **Public data** tab. **The files** lists, for each well, the file to download, its size, its hash, and the page of the Geothermal Data Repository it is on (a link). Download them into one folder - two wells or more make a pad; about 2.8 GB for all five - then, as an administrator, name that folder and **Check the folder** to see which are there, name a new folder for the site, and **Make the site**. Making it takes some minutes: each file is hashed, the three layouts that are not the recorder's own export are written out as one, and each well is attached. The new site is listed under Administration, Workspaces, and opens in its own window like any other. From a terminal: `gea public-pad --list` prints the files and where each is published; `gea public-pad --folder C:\forge` says which are in the folder; `gea public-pad --folder C:\forge --verify` hashes them; `gea public-pad --folder C:\forge --build --site C:\forge-site` makes the site, or adds to it the wells it does not have yet; `gea public-pad` alone runs the self-test on stand-ins in each published layout.

**What it writes**: the site's workspace in the folder named, with each well attached, and `records/public_pad.json` in it - the dataset, the licence, the credit, and for each well the source file, its size and SHA-256 as found, whether they match, and what was done to it; a line `public_pad.build` in its audit log. Every page and report of that site then ends with the credit line the licence asks for. Nothing is written in the folder the files are in, and nothing is sent anywhere.

**What is done to each file**: `56-32` and `78B-32` are the recorder's own one-second export and are attached as they are. They carry no on-bottom flag, so the drilling record takes on bottom as the bit within 0.1 ft of the hole depth, and says so. `16B(78)-32` is a ten-second export of over a hundred channels inside a zip: the channels the program reads are written out, and the true vertical depth is added from the well's own published survey when `16B(78)-32 Well Survey.zip` is in the folder too - the hole is deviated 65 degrees, and without the survey its measured depth stands in. `58-32` is the 2017 recorder in another layout: its U.S.-unit columns are written out under the names the program reads; it has no weight on bit and no differential pressure, and the pages that need them say so for it. `16A(78)-32` is another recorder's layout with no bit depth: the bit depth is RECONSTRUCTED - the hole depth while the on-bottom flag is set, unmoved while the slips are set, otherwise moved by what the block moved - exact on bottom, approximate over a trip, and marked as reconstructed on every page that uses it. Two things in these records the drilling record now reads that it did not before: a depth set back thousands of feet and regained through hole already drilled, with a fraction of the weight on bit it was drilled with, is the string reamed back in with the depth tracker counting (REAMED BACK, excluded - `gea help edr`); and a ten-second record's pipe speeds are taken over two samples either side, where five seconds held no two samples.

**The number to check**: each well's total depth and dates against its published end-of-well report on the same repository page; the hash of each file against the one printed here - `gea public-pad --folder C:\forge --verify`. A file whose hash differs is used all the same and said to differ: the repository revises its files, and the figures may then differ from another site's.

**What this page will not call a measurement**: the reconstructed bit depth of 16A(78)-32, and so that well's trip speeds; a true vertical depth where the measured depth stands in for one; a comparison between these wells as like for like - they were drilled six years apart, in three hole sizes, two of them deviated, with the bits of their day; the hashes as a warrant of the data - they say a file is the one this release was checked with, not what the recorder recorded; and anything about a client's wells - this is a pad to learn the pages on and to show their figures with, and its rock is granite.
