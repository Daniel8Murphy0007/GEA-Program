# The QuakeML catalogue export

> The site's own events - what its stations located together - in QuakeML 1.2, the exchange format a regulator's catalogue tool, a university network's review desk and every seismological package read.

**The command**: `gea workspace --path C:\site --action quakeml-export --site <id> [--agency "<name>"] [--out <file.xml>]`, after `--action associate` has run on the site (the export is built from `reports/sites/<site>/association.json`). `--agency` is the agencyID written in every creationInfo; the site's name by default. `gea quakeml` runs the self-test on the association leg's labelled scene and leaves the file where `--out` says.

**What it writes**: `reports/sites/<site>/quakeml/<site>_events.xml` - a `q:quakeml` document in the QuakeML 1.2 namespaces, built to the Basic Event Description schema (QuakeML-BED-1.2.xsd): one `event` per associated event with its `origin` (time; latitude and longitude with the misfit region's half-extent as their uncertainty in degrees; depth in metres with `depthType` "operator assigned", because the depth was declared; `methodID` and `earthModelID` naming the grid search and the one-velocity flat-earth model; `quality` with the station and phase counts, the RMS as standardError, the azimuthal gap and the epicentral distances in degrees; `originUncertainty` with the misfit region in metres), one `pick` per station that made the event (the onset time with the pick uncertainty, the record's own FDSN codes in `waveformID`, phaseHint P), and one `arrival` per pick on the origin (azimuth, distance, the residual, weight 1). Every origin and pick is `evaluationMode` automatic and `evaluationStatus` preliminary. The catalogue's standing - AGREES, DIFFERS with both positions, NOT IN CATALOGUE - is a comment on the event with the catalogue's own event id. `export_summary.json` beside it carries the counts, the gaps and the shape check. Every export is in `records/audit.jsonl`.

**The number to check**: `shape VALID_SHAPE` on the second line - the first checks a QuakeML reader makes, made here first: the namespaces; every publicID to the schema's ResourceIdentifier pattern and used once; every child element one the schema allows for its parent; time, latitude and longitude on every origin; time and waveformID on every pick; every arrival's pickID a pick of the same event; every event's preferredOriginID one of its origins; every enumerated value in its enumeration. A `gap:` line names a station whose record carried no network and station code (written under the test network XX with the station id) or no position (its arrival carries no azimuth or distance).

**What this page will not call a measurement**: a magnitude - the association does not estimate one, the file carries no `magnitude` element, and a comment on every event says why. The catalogue's events as this site's - they are the catalogue's to publish; the file names them in comments and carries only what the site's own stations located. A reviewed or final event - a person has not looked at these, and the file says automatic and preliminary in the schema's own words. A located depth - it was declared, and `depthType` says so. A full schema validation - the shape check is what a reader reads first, not a validator; the file was validated against the published XSD when this export was written, and the check here holds it to that shape.
