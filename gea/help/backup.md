# The backup

> The records are the product. A lost disk is a lost month unless the site is copied off the machine every day - and a copy nobody has restored is a hope, not a backup. This page is the command that copies, the one that checks, and the one that brings it back.

**The command**: `gea backup --workspace C:\site --out D:\gea-backups --keep 14` writes one dated archive, `gea-site-<name>-<UTC>.zip`, into a folder that must be on another disk or a share (a folder inside the workspace is refused). On the dashboard, Audit / Update -> The backup: set the folder, Back up now (a job), Schedule daily (a schedule entry, `backup-daily`, at the hour given, UTC). `gea backup --verify <archive>` checks every file in it against its manifest and the archive against its `.sha256`. `gea backup --restore <archive> --to C:\site-restored` extracts onto an empty folder, verifies every file again, opens the result as a workspace and says what came back; then `gea serve --workspace C:\site-restored --port 8766` and look. `gea backup --workspace C:\site --status` prints when the last one was taken; the doctor prints the same line and warns when there has never been one or the last is more than 26 hours old.

**What it writes**: the whole site - every well's source files and records, every seismic station's source and live day files, `config/`, `monitor/`, `reports/`, `users.json`, `records/` (the audit log, the notifications, the patches, the certificates, the swaps), `workspace.json` and `jobs/schedule.json` - with `MANIFEST.json` inside (the program version, the site name, the time, every file's SHA-256 and size, the wells and stations by id) and `<archive>.sha256` beside it. Left out: the job run folders and the upload scratch, which are reproducible and are what grows. Each backup is logged in `records/backups.jsonl` and in the audit log (`backup.make`); a restore writes `restored_from.json` in the restored folder and `backup.restore` in its audit log. `--keep N` prunes the older archives of this site in that folder.

**The number to check**: on the card and in the doctor, `current` with the hours since the last backup, or `NEVER` / `STALE`; on `--verify`, `OK` with the file count and "archive hash matches"; on `--restore`, the well and station counts and `users.json present`.

**What this page will not call a measurement**: a backup that was never restored - run the restore once onto an empty folder and open the page. An archive whose manifest does not match its files - `--verify` says FAIL and names them, and `--restore` refuses it. A copy on the same disk - the folder inside the workspace is refused; a second folder on the same drive is not refused, and is not a backup either. The job run folders - they are not in the archive, by design.
