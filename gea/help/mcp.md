# Assistant access (MCP)

> The site, readable by an assistant. A chat program that speaks the Model Context Protocol can be given this program as a tool box: it starts `gea mcp` as its own child process, asks what tools there are, and calls them. Each tool is one of this program's pages - the rig time, the roadmap, the drilling alerts, the fluid balance - read out as the text the command line prints, so what the assistant says about the site is what the program says. It is local (it listens on no port), read-only (no tool declares, attaches, removes, writes or sets anything) and logged (every call is a line in the workspace). What a tool returns goes into the assistant's conversation, and so to whoever runs the model behind it: offering a tool is deciding that its page may leave the site.

**The command**: the **Assistant access** tab. **Add to Claude Desktop** (an administrator) writes one entry, `gea`, into Claude Desktop's own configuration file on this computer, keeps every other entry and leaves a dated copy of the file as it was; then quit Claude Desktop completely and start it again, and the tools are under its connectors. **Take it out of Claude Desktop** removes the entry the same way. For any other MCP client, **Copy** the entry shown and paste it into that client's configuration. **The tools** table is the choice of what an assistant may read: untick a page that must not leave the site and **Keep** (an operator), with who decided and on what grounds; a tool not offered is not listed to the assistant and cannot be called. **The access log** shows the last calls. From a terminal: `gea mcp --workspace C:\site` is the server itself - it waits on its standard input and is what the assistant runs, not something to start by hand; `gea mcp --workspace C:\site --status` prints the tools offered, how to start it and the last calls; `gea mcp --workspace C:\site --config` prints the entry for a client's configuration; `gea mcp --workspace C:\site --call roadmap` prints one tool's answer as an assistant would get it (`--well` names a well, `--json` asks for the page as JSON); `gea mcp --workspace C:\site --offer site,rig_time,roadmap,drilling_alerts,help --source "site manager, 2026-11-13: drilling pages only"` keeps the choice (`--offer all` offers every tool again); `gea mcp --workspace C:\site --add-to-claude-desktop` and `--remove-from-claude-desktop` do what the buttons do; `gea mcp` alone runs the self-test.

**What it writes**: `records/mcp_access.jsonl` - a line a call: the time, the tool, its arguments, the client as it names itself, whether it answered, how many characters and how long, and a call for a tool that is withheld or does not exist as turned away (the file is set aside as `.1` when it passes 5 MB). `records/mcp.json` when the choice of tools or the limit is changed (audit line `mcp.settings`). Claude Desktop's `claude_desktop_config.json` and a copy `claude_desktop_config.json.before-gea-<time>` beside it, only when the button or the command is used (audit line `mcp.claude_desktop`). Nothing else: no tool writes a record, a declaration, a report or a setting. Reading a page for the first time may build that well's chart cache, as opening its tab would.

**The tools**: `site` (the wells), `well` (one well as declared), `rig_time`, `drill_string`, `roadmap`, `drilling_alerts`, `torque_drag`, `hydraulics`, `pore_pressure`, `casing`, `collision`, `plan_vs_actual`, `frac_hits`, `fluid_balance`, `pressure_plume`, `fluid_front`, `calibration` (the kept result; it runs nothing), `decline`, `invoice_check`, `seismicity`, `alerts`, `audit` and `help`. Those that read a well take `well`, by name or id; `alerts` and `audit` take `n`; `help` takes `topic`; every tool but `help` takes `json` for the page as the program's own structure instead of its text. An answer longer than the limit (40,000 characters unless changed) is cut and says so. Each tool declares itself read-only to the client, which is the client's cue not to ask for confirmation on every call - and is true.

**The protocol**: JSON-RPC 2.0, one message a line, on the standard input and output of the process the client starts; anything the program would otherwise print goes to the error stream. Two eras are spoken, chosen by how the client opens. A client of revision 2026-07-28 sends each request with its protocol version in `_meta` and is answered statelessly, every result carrying `resultType`, with `server/discover` for the versions and capabilities; a version it does not speak is answered with error -32022 and the versions it does. A client of 2025-11-25, 2025-06-18, 2025-03-26 or 2024-11-05 opens with `initialize` and is answered with the handshake of the revision it names. Tools only: no resources, no prompts, and nothing is ever asked of the client. An unknown or withheld tool is error -32602; a well that does not exist or a page that cannot be computed is an ordinary answer marked as an error, with what to do about it.

**The number to check**: one tool's answer against its tab - `gea mcp --workspace C:\site --call rig_time` beside the Rig time tab: the same figures, because it is the same function; and the access log's count of calls against what was asked of the assistant. On the self-test `gea mcp` runs, a client of each era opens against a labelled site, lists the tools and calls them; a line that is not JSON, a tool that does not exist, a well that does not and an argument a tool does not take are each answered as what they are; a withheld tool is not listed and cannot be called; and the entry is added to a configuration file with its other entries kept, and taken out again.

**What this page will not call a measurement**: privacy - the server is local, the assistant is not, and nothing here controls what the assistant's maker does with what it is given; the assistant's answer - a tool returns the program's page, and what the assistant then writes about it is the assistant's, to be checked against the page; who is asking - a client names itself, and that name is logged as given, not verified; a SIMULATION - the plume, the front and the calibration are projections here exactly as they are on their tabs, and say so in their first line; silence - a page that says nothing is declared has no figures, and an assistant that supplies some did not get them from here.
